I meant to additionally mention what appears to be a significant, negative side effect of the changes I made.  Another .NET application of mine, FileDir, no longer launches.  There is an immediate error related to some security DLL of the .NET Framework.  This application was working before I updated to the latest JAWS 11 and made the recommended ini changes.  I completely reinstalled the program to no avail.  I wonder if the JAWS installer/updater is interacting with the .NET Framework in some way that produces this side effect.

I recognize that this may be an absolute coincidence on my home computer (Vista 32).  Still, I should report this as an alert since I have not experienced this problem before, and as mentioned, was actively using FileDir before I did this testing.  I have been primarily using JAWS 10 on this computer, so had not checked for an updated JAWS 11 in a few months.  The update process went smoothly, however -- no problems were reported.

In case FS wants to try FileDir and see if the same problem is encountered, the installer is at
http://EmpowermentZone.com/dirsetup.exe

>> Well guys, as the says goes, "The grass isn't growing under our feet

>> I've just had the following from my contact at Freedom Scientific.

>> George.
>>
>>
>> It would be helpful if you could provide some additional feedback
>> after reading the following.
>>
>> Please make sure you have the latest JAWS update installed before
>> continuing. Updating later on version 11 may become tricky and result
>> in having to uninstall and remove shared before getting any further
>> updates.
>>
>> The problem is related to the fact that JAWS isn't directly
>> communicating with the RichEdit controls used inside .net
>> applications.
>> Under these circumstances when JAWS is using the OSM to do a SayAll,
>> it is not always possible to reliably detect the bottom of the
>> document.
>> This, as was hypothesized, is why the system seems to stop functioning
>> until Alt+Tabbing away from the application.
>>
>> The potential fix involves two steps:
>> 1. Go into Configuration Manager for the application in question,
>> choose Text Processing Options and then enable Extended Edit Support.
>>
>> 2. Add the following lines to the bottom of FSDomSrv.ini in the
>> C:\Program Files\Freedom Scientific\Shared\FsDomSrv\2.0 directory
>>
>> [RichEditInDotNet]
>> DLLName=FSDomNodeRichEdit
>> MappingFlags=128
>> WindowClass=WindowsForms10.RichEdit20W
>> InteractionModeFlags=2
>>
>> Restart both JAWS 11 and the .net application.
